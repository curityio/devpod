To get started with DevPod, choose either the [DevPod Desktop](#install-devpod) application or the [DevPod CLI](#install-devpod-cli).

## Install DevPod

Download DevPod Desktop:
- [MacOS Silicon/ARM](https://github.com/curityio/devpod/releases/latest/download/DevPod_macos_aarch64.dmg)
- [MacOS Intel/AMD](https://github.com/curityio/devpod/releases/latest/download/DevPod_macos_x64.dmg)
- [Windows](https://github.com/curityio/devpod/releases/latest/download/DevPod_windows_x64_en-US.msi)
- [Linux AppImage](https://github.com/curityio/devpod/releases/latest/download/DevPod_linux_amd64.AppImage)
- [Linux Targz](https://github.com/curityio/devpod/releases/latest/download/DevPod_linux_x86_64.tar.gz)

:::info Previous Releases
For earlier versions, visit the [GitHub releases page](https://github.com/curityio/devpod/releases)
:::

:::info Linux Packages
**The official package is the Appimage**, it has been tested working on:

- Debian 12 and newer
- Ubuntu 22.04 and newer
- Fedora 36 and newer
- Opensuse Leap 15.3 and newer
- Opensuse Tumbleweed
- Archlinux

Make sure you have the following dependencies installed for the Appimage to work (usually already installed in desktop distributions):

- glibc version 2.35+
- fuse2, fuse2 libraries, libopengl, libfribidi, libegl, libxgl
    - `sudo apt-get install fuse libfuse2 libopengl0 libfribidi0 libgles2-mesa`
    - `sudo dnf install fuse fuse-libs libglvnd-egl libglvnd-opengl libglvnd-glx harfbuzz fontconfig fribidi libthai`
    - `sudo zypper in fuse libfuse2 libharfbuzz0 libfribidi0 libthai0`

These are generally needed for AppImage to work; they are not specific to DevPod.
:::

:::info Windows Packages
Make sure you have the following dependencies installed for the Desktop App to work:

- [WebView 2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/?form=MA13LH)

Note that WebView 2 is normally already installed on recent versions of Windows and should not need installing unless you experience issues.
:::

:::info Linux Custom Packages
Since we're not providing deb or rpm packages anymore, we're now providing a tar.gz
that can be used as source for your custom package.

Keep in mind the following dependencies need to be declared in the package for the
correct functioning of the program:

- libappindicator3-1
- libgdk-pixbuf2.0-0
- libbsd0
- libxdmcp6
- libwmf-0.2-7
- libwmf-0.2-7-gtk
- libgtk-3-0
- libwmf-dev
- libwebkit2gtk-4.1-0
- librust-openssl-sys-dev
- librust-glib-sys-dev

On Fedora: `sudo dnf install libappindicator-gtk3`
:::

## Upgrade DevPod CLI

`devpod upgrade` replaces the CLI with the newest stable release, if it is newer than the one you have.
Pre-releases (such as `v0.9.0-alpha.1`) are never picked, but you can install one, or go back to an older
release, with `--version`:

```bash
devpod upgrade --version v0.8.0
```

To only check whether a newer version is available, without downloading anything or touching the CLI, run the
following. It fails if the upgrade would fail, for example because the current user can't replace the CLI.

```bash
devpod upgrade --dry-run
```

The upgrade needs to create files in the directory the CLI is in. If you installed it in `/usr/local/bin` as
shown above, run it with `sudo`. If the GitHub API rate limit stops it, set `GITHUB_TOKEN` to a GitHub token.
The new CLI gets the mode, owner and group of the one it replaces. Without root, the upgrade can't make another
user its owner, or give it a group you aren't in; then it warns about what it couldn't keep and shows the `chown`
command that fixes it.

If you run the CLI through a symlink (for example `~/bin/devpod` pointing to `~/tools/devpod-v0.8.0`), the upgrade
doesn't replace the file the link points to. It downloads the new release next to that file, named after the
release (`~/tools/devpod-v0.9.0`), and points the link to it, so the previous release stays where it was. This
needs permission to create files in both directories. A symlink to another symlink isn't supported.
